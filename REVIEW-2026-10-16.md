# Full feature review — 2026-10-16

Read-only review of the whole codebase (~800 files), split into 8 areas. Items already open in TODO.md / ENHANCEMENTS.md are left out unless they're marked done but broken. Findings are from reading code; nothing was run. Ones marked ✔ were re-checked by hand.

Severity: **H** = can lose money, data, bookings, or create legal exposure. **M** = wrong behavior a salon will hit. **L** = edge case / hygiene.

## Themes worth fixing once, not per bug

1. **One guarded appointment state machine** — every cancel/no-show/reschedule (web, drag, API, mobile, class, series) goes through `setAppointmentStatus` with legal transitions, reason, deposit handling and reminder resync. Reminders scheduled on booking, independent of the confirmation.
2. **Stripe call pattern** — never call Stripe inside `withTenant`; pending row → commit → Stripe with stable key → settle; store `stripe_account_id` on every payment, membership and price.
3. **Client identity** — attach online bookings/forms to an existing client only when signed in or phone+name match; otherwise create and flag a duplicate; add a merge tool.
4. **Consent model** — marketing opt-in default false, separate from transactional; consent records; business-wide suppression list checked inside `send()`.
5. **Permissions** — nobody grants what they don't hold; own-only scoping for sales and mobile; refunds/discounts/gift-card issue/pay settings behind their own permissions; audit role/member/time/payroll changes.
6. **Payroll periods as ledgers** — finalized snapshot is the source of truth; later refunds/changes land as adjustments in the next open period.
7. **Observability** — API 500s and job sub-step errors reach `ERROR_WEBHOOK_URL`; health endpoint; tests for money, booking and messaging engines (currently the biggest untested surface).
